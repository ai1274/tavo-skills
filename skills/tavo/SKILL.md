# Tavo

先确认任务对象、当前项目规则和交付物。模型已选中能完成交付的专项时，直接使用该专项。用户调用 `$tavo`、任务跨专项或需要判断分支时，按下表选主分支，并按阶段选用配套流程。显式将 `$tavo` 用作通用入口时，跟随当前项目流程进入配套路由。

按表读取同级技能，已加载的直接复用。用户指定的技能、启用策略和目标项目规则继续生效。技能缺失或停用时用现有项目证据继续，影响结果时说明限制。

| 用户要交付什么 | 读取主分支 |
| --- | --- |
| 解释平台能力、配置、接口区别，或编写独立预设 / 世界书 / 正则 / EJS 内容 | [平台文档与内容编写](../tavo-skill/SKILL.md) |
| 连接或诊断 MCP、查看 MCP 的工具/资源/schema、比较指定 MCP 版本，或经 MCP 执行被授权的操作 | [MCP 与版本证据](../tavo-1-0-beta-skill/SKILL.md) |
| 新建、修改、调试、构建或实测优化 TPG / TavoJS / 主题 / WebView 及插件数据链路、服务，包括 App 右侧边栏、插件内技能应用与自动配置；核验包结构、PNG 封装或导入链路 | [工程实现与验证](../tavo-studio/SKILL.md) |
| 编写或审查角色卡套件，连同配套世界书、角色输出约束或卡内正则 | [角色卡设计](../tavo-character-card/SKILL.md) |
| Tavo 方案已定，单独交付具体改哪里、哪些是生成物、用什么最小回归证明 | [主线最小开发](../tavo-mainline-minimal-development/SKILL.md) |
| 确定仓库或插件包维护边界、任务合同、Writer 分工与合并门禁，或判断验收、归档条件 | [项目架构与工作流](../tavo-memory-steward-clean-workflow/SKILL.md) |
| 诊断或操作工具本身，例如路由漏匹配、校验误报、Registry 或 Project Map 过期、项目内 RAG/Graphify 接线、Hook 或发布脚本故障 | [项目工具链](../tavo-project-tooling/SKILL.md) |
| 明确要求执行 Graphify 操作，或使用已有 `graphify-out` 作为独立交付 | 按项目已有 Graphify 流程执行 |

“TPG 的 `minAppVersion` 怎么定”走平台问答。“改这个 TPG 并打包”走工程，现有测试和门禁也由工程运行。“连接服务器看看该字段是否暴露”走 MCP。卡自带的世界书和正则走角色卡，单独写世界书走平台。需要第二项交付时，到了该阶段才加载相关分支。例如角色卡写完后，经授权用 MCP 核对导入 schema。

同一任务需要分工验收与源码范围时，先由项目工作流确定包、合同和门禁，再由主线锁定源码路径及回归。工具异常需要单独诊断时，带上工作目录、输入、命令和报错交给工具链，并把诊断回传给负责门禁的分支。

**插件优化**。新建、开发功能、修复或维护插件时，默认进入 `tavo-studio` 的[插件优化流程](../tavo-studio/references/plugin-performance.md)。在当前范围内完善和补齐已证实的功能缺口，对实测瓶颈实施最小优化并复测。每次交付插件更新都按[版本与更新日志规则](../tavo-studio/SKILL.md#插件版本与更新日志)更新版本号和本版说明。用户提供 Tavo MCP 地址时，用该实例执行[真实验证](../tavo-studio/SKILL.md#开发时用-mcp-验证)。诊断按任务的读写范围执行。

## 按需使用配套流程

接口或实现不熟悉时，先看项目约定和已有知识库。整体改版先确定视觉方向，复杂界面再做布局、响应式和可访问性决策。关键 WebView 交互做定向审计。可复现缺陷和非平凡行为先建回归基线。仅在任务明确需要时查询或更新 Graphify。客户端已安装适用的设计、Web 审计、TDD、知识检索或 Graphify 技能时，可按工作阶段使用。

这里的 Agent Skills 供客户端使用。涉及 Tavo App 内应用技能时，先定位真实 TPG 和执行入口，再查[侧栏技能应用](../tavo-studio/references/sidebar-skill-application.md)。

**查官方技术文档：**先按交付物选分支；已知页面就直接读。接口名、配置项或术语涉及多页、章节不明时，再用[官方 URL 索引与离线检索](../tavo-skill/references/01-official-url-map.md#search-the-official-snapshots-offline)。检索结果用于定位原文，不改变分支、证据级别或操作授权。

**Tavo MCP 同机示例**为 `http://127.0.0.1:7347/mcp`。真实验证使用用户为当前任务提供的地址，首选直连 HTTP JSON-RPC。Bearer 由用户在当次运行注入，仅发往获授权的地址。Tavo 插件开发按[工程分支的验证闭环](../tavo-studio/SKILL.md#开发时用-mcp-验证)执行。

隐式触发以交付物是否依赖 Tavo 为准。仅处在 Tavo 目录、提到名称或翻译日志均不触发。先由当前目录和最近规则定位项目对象。不同 owner 会改变结果且无法消歧时再询问。

声明、schema、离线测试、宿主行为分别取证。分析、构建与宿主操作权限分开；未经授权不安装、不写用户数据、不调用 provider、不发布。不要输出或保存凭据。
