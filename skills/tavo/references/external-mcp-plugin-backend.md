# Tavo 插件与外部 MCP 后端

## 项目结构

新建分离式插件以 `tavo-plugn/世界书向量化/` 的源码结构为模板（案例源码不随本技能仓库分发），在自己的工作区建立一个独立项目目录。既有项目在原位置维护，不仅为对齐模板就迁移目录。

```text
<项目名>/
├── AGENT.md / README.md        # 项目规则、启动、连接与验收
├── manifest.json / package.json # TPG 清单、项目命令与版本
├── src/                       # TPG 入口、面板、宿主适配与出站 MCP 调用
├── backend/                   # MCP 入口、业务、依赖/锁文件及后端测试
├── test/                      # TPG 与前端 MCP 适配回归
├── scripts/                   # 当前项目的构建与发布脚本
├── dist/                      # builder 生成的前端包
└── release/<项目名>-<版本>/    # builder 生成的配套交付文件
```

按需沿用 `assets/` 和 `config.example.json`。不复制案例业务、运行数据库、虚拟环境或生成物；项目 README 写当前命令及前后端责任。项目内 `release/` 与用户指定的 `1项目/` 交付归档分开，均不作为开发位置。

## 工程分工与工具契约

1. **TPG 前端**负责面板/WebView、表单、界面状态和 Tavo 宿主交互。收集并初步校验参数；需要宿主数据时只发送业务所需的字段。收到结果后核对格式和当前对象，再显示结果或执行获授权的宿主操作。展示加载、空结果和错误；请求超时、取消或切换会话后，不应用迟到的结果。
2. **Tavo 出站 MCP**负责连接。插件用宿主已启用的连接 ID 找到服务，再按已核对的工具名传参。地址和认证头留在 Tavo 连接配置中，不写进 TPG。工具契约写明稳定的工具名、`inputSchema`（必填参数及范围）、结果字段（支持时声明 `outputSchema`）和错误；两端改动时一起检查兼容性。区分权限拒绝、连接失败、业务错误和无结果，不把失败显示为成功。
3. **独立后端**负责鉴权、最终输入校验、业务计算、外部服务调用和业务数据持久化，以 MCP 工具结果返回可校验的业务数据或错误。应用侧配置与密钥按各自归属保存，响应和日志不回显秘密；后端不直接操作 Tavo 宿主。

开始实现前，先从目标项目的合同、README、前后端入口和测试确认命令、工具名及数据边界。复用项目已有后端与构建方式；FastMCP、端口、工具名及数据文件只是下面案例的选择。验收至少覆盖前端参数和结果处理、后端业务测试、MCP 工具一次成功及一种关键失败。未获授权或缺少实际 Tavo 实例时，只做本地或模拟验证并标明宿主未验，不调用真实 provider 或写入用户数据。

## 同机出站 MCP：回环 IP 与随机端口

1. **后端启动**：同机新项目默认只监听 `127.0.0.1`，以端口 `0` 请求操作系统在实际监听时分配空闲端口。不要先探测再释放套接字，也不要写死端口。启动成功后显示可直接复制的 `http://127.0.0.1:<实际端口>/mcp`；`0` 不是客户端端口。服务应保留对 Host 和浏览器 Origin 的校验。不监听 `0.0.0.0` 或局域网地址；无令牌、请求头留空的配置只用于回环连接，和业务模型的鉴权无关。
2. **Tavo 连接**：在「更多 → MCP」添加并启用 Streamable HTTP 连接，只需填写上面的 URL（用户只需知道本机 IP 和实际端口，路径固定为 `/mcp`）。保留 Tavo 的「调用 MCP 工具」权限与确认。插件通过 `tavo.mcp.list()`/`get(id)` 选择已配置的服务，以连接 ID 绑定；用 `listTools()` 检查所需工具，再调用一个无副作用的工具确认链路。插件不保存地址、不扫描端口，也不依赖 Tavo 自己的入站管理 MCP。
3. **重启与验收**：重启可能得到新端口。用本次启动输出更新原 MCP 条目的 URL，确认仍启用，再刷新工具列表并重开面板；若原条目不能编辑或连接 ID 变了，重新选择服务。用临时数据检查实际监听端口不是 `0`、工具可发现且能返回结果；停服时插件提示不可用并按项目合同降级，不沿用旧结果。

## 完整版本归档

继续在原项目目录维护和测试源码。完成版本更新后，用项目已有 builder 生成配套产物。前端、后端、MCP 及打包检查通过后，整版交付时在用户指定的 `1项目` 归档根下新建 `<项目名>-<版本>/`；归档根位置不明确时先核实，不另猜一个同名路径。归档不是源码副本，也不代替原项目的 `release/`。分开记录本地验证和实际宿主验证，不能用打包通过代替必须的联调验收。

以 `世界书向量化/release/世界书向量化-1.5.0/` 为例，前端、后端和说明放在同一级：

```text
1项目/
└── 世界书向量化-1.5.0/
    ├── worldbook-vectors.tpg
    ├── worldbook-vectors-python.zip
    └── README.md
```

- **前端**：可导入的 `.tpg`。**后端**：项目规定的可运行交付包；示例 ZIP 含启动入口、业务代码、依赖及空白示例配置。**README**：兼容版本、导入和启动步骤、出站 MCP 配置及最小验收方式。
- 核对前后端来自同一验收版本、归档文件与 builder 输出一致，且不含真实凭据、已填写的配置、数据库或用户数据。按项目既有命令验证，不覆盖已有版本目录；只改技能或项目仍在开发时不提前归档。
- 案例命令：原项目用 `npm run verify` 验证前端，后端命令见下文。项目根的 `npm run release` 生成配套文件，`npm run release:check` 验证产物一致性；其他项目以自己的命令为准。

## 案例：世界书向量化 1.5.0

插件读取 Tavo 资料库、核对检索结果并在生成前注入正文；Python FastMCP 负责模型配置与调用、SQLite 索引、召回和重排。以下是电脑同机接入与验收示例。

### 1. 在电脑上启动后端

先让 Tavo 和 Python 在同一台电脑上运行。从 `tavo-plugn` 工作区根目录执行：

```powershell
Set-Location -LiteralPath '.\世界书向量化\backend'
$env:WBV_HOST = '127.0.0.1'
$env:WBV_PORT = '0'
$env:WBV_TOKEN = ''
uv run --python 3.11 python server.py
```

保持进程运行，以 Uvicorn 的 `Uvicorn running on` 日志为准，把实际监听地址加上 `/mcp`；前面的 FastMCP 启动提示可能仍显示 `:0`。案例 1.5.0 未设置 `WBV_PORT` 时仍默认使用 `37892`，上面的命令无需改源码即可切换到随机端口。SQLite 默认在 `backend/data/worldbook-vectors.sqlite3`；临时联调可用 `WBV_DB` 指向测试库。在同一目录运行 `uv run --python 3.11 python -m unittest discover -v`，可用临时数据库和模拟模型检查后端行为。

### 2. 在 Tavo 添加出站连接

按上面的同机连接流程填写实际 URL，请求头留空。工具列表至少应包含 `wbv_profiles` 和 `wbv_retrieve`。若在该项目中明确启用了 `WBV_TOKEN`，才按它的配置填写对应的 Bearer 请求头。

### 3. 让插件使用已启用的连接

1. 导入并启用世界书向量化 TPG，开启高级渲染并重新进入聊天。打开聊天右侧栏的「选择世界书后端」，选刚启用的 Python 服务。打开或重开「世界书向量化」面板，确认标题下方显示 `Tavo · Python MCP`。
2. 用 `callTool(name, args)` 按工具原名调用。处理拒绝时的 `null`、工具返回的 `isError` 和连接异常。[TavoJS 官方 API：MCP 服务](https://docs.tavoai.dev/cn/guides/javascript-api/)

### 4. 验收与排错

1. **插件调用。**打开「模型配置」确认能读取列表。空列表表示当前后端尚无模型配置。首次切换到 Python 后端时，配置向量和重排模型，授权后分别使用「测试连接」核对返回。
2. **业务验收。**使用一条虚构世界书条目，例如标题「白塔灯」、正文「白塔灯在入夜后照亮北港」。在「世界书向量」中勾选并生成索引，在「重排发送」选择已授权模型并设置包含该书的注入规则。发送匹配问题，例如「北港入夜后由什么照亮？」，到 Tavo 上下文日志检查「插件」块的正文、数量、顺序和位置。SQLite 保存索引、正文及模型密钥，使用测试数据并保护数据库及备份。
3. **离线行为。**在可中断的测试环境停止后端再发一轮，预期聊天继续生成并跳过本轮注入。重启后按实际端口更新连接，再重开面板确认业务调用恢复。

连接列表缺少服务时，检查后端是否仍在运行、Tavo 是否启用了正确地址，以及工具目录是否包含业务工具。列表可读但调用失败时，检查脚本权限、用户确认、工具返回和后端日志。模型连接失败时，从运行 Python 的环境检查模型端点、DNS 和鉴权。索引成功但未注入时，检查勾选范围、有效索引、注入开关和上下文日志。

世界书向量化的电脑实测已确认 MCP 工具可发现、模型配置可读取及面板可切换为 `Tavo · Python MCP`。该次电脑联调的模型配置为空，真实模型调用、建索引、检索注入和离线行为仍需按上述步骤验收。

跨设备不适用本节的无令牌配置。维护已有跨设备项目时，保留其网络、认证和加密规则，不把回环地址换成网卡地址后直接开放。案例的手机 Runner 管理 MCP 和 Python 业务 MCP 是两个服务。
