# Tavo 主线最小开发

以已定方案、目标项目和可观察结果为输入。普通实现中的代码搜索由实施分支自行完成。需要单独厘清改动范围，或实施过程中发现 owner 冲突时，在动手前用本技能锁定范围。方向未定时先解决会改变实施的方案歧义。

1. **定目标。** 写出一个可观察变化及必须保持不变的行为。确认目标项目，不从 `Memory Center` 推断是旧记忆管家，也不把多个 TPG 当成单一包。
2. **找 owner。** 当前项目规则 → 相关合同 → 真实入口、调用方和负责该行为的测试 → 当前 `package.json`、builder 或对应的命令配置。仓库位置不明时用[项目结构速查](../tavo-memory-steward-clean-workflow/references/project-architecture.md)定位，再读目标目录证实。遇到归档或生成物，从 builder 或调用方追到维护源。只有当前运行时合同影响范围时才查对应官方资料或经授权发现。
3. **锁最小范围和回归。** 为每个维护源文件记录改动理由、相关调用方和派生物，列出要保留的接口或状态。记录回归的命令或检查入口、输入和可观察的预期结果，附适用的回退方式。行为修复优先设计能区分修复前后的用例，文档和配置检查实际引用或结构。owner、依赖、权限或数据影响变化时重新核对范围。
4. **交付可复核的范围。** 交接包含项目根、当前合同或源码证据、允许改动的路径、验收入口和预期结果。区分已证实、推断与待核实项。仅规划时交付到此，列明尚未运行的检查。已授权实施时把这些信息交给实际工程分支，由其修改源码、按需生成并验证产物。仓库需要 Writer 集成或验收判定时，把实际结果交给项目工作流。
