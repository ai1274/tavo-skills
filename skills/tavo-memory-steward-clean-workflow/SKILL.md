# Tavo 项目架构与工作流

旧 ID 供显式调用兼容，不等于当前目标是旧 Memory Steward 单仓。需要定位工作区时读[项目结构速查](references/project-architecture.md)；项目现状最终由目标目录的当前文件确认。

1. **区分目标和权限。** 查询架构、做验收建议只读；实施仅在已授权的目标工程原目录进行。先读根及就近规则，再按当前合同、源码/测试、包配置及 builder 定位。合同与实际行为冲突时指出差异，不用旧日志或生成图谱裁决。
2. **按风险定流程。** 小文档或接线只跑有针对性的结构和引用检查；确定性行为做最小回归；领域边界发生变化时才补例子与不变量。S0–S3、`requirements.md` / `design.md` / `tasks.json` / `findings.md`、任务登记、phase barrier、发布账本等只在目标仓库当前规则实际要求时采用。
3. **分离责任。** 有授权且确有独立工作时，Scout 只读；Writer 路径互斥，主 Agent 持有共享控制文件、串行集成及最终验收。不强制平行、不复制工作目录、不回写来源工程，不把历史交付物当作源码。
4. **按对象验收。** 局部检查先于目标包最终验证；构建用实际 owner 生成产物。保留现有用户改动；说明跑过的检查、未验证项和回滚方式。完成与发布/归档权限是两回事，不因通过门禁擅自写宿主、提交、发布或归档。

有共享资源的项目先查根规则与资源校验入口。产品变更按各包的实际入口、门禁和范围验收。
