# Tavo 项目架构与工作流

沿用历史技能 ID。根据目标目录确认任务属于当前 Memory Center、旧 Memory Steward 或其他 Tavo 工程。需要定位工作区时读[项目结构速查](references/project-architecture.md)，再用目标目录的当前文件核实。

1. **确认目标和授权。** 输入是目标仓库或包、要做的流程判断及可用验收证据。读根和就近规则、当前合同、包配置与 builder，分清维护工程、生成产物和历史来源。合同与行为冲突时指出差异。架构查询和验收建议保持只读，实施仅在获授权的工程原目录进行。
2. **选门禁。** 把要验收的合同条目对应到目标包、聚焦回归与必要的最终检查。小文档或接线检查结构和引用。S0–S3、任务登记、合同套件、阶段门禁和发布账本按目标仓库当前规则启用。
3. **分工与集成。** 有独立工作时，Scout 只读，Writer 只改互斥路径。派发前提供合同或验收条目、目标工程、允许路径和检查入口。需要锁定具体源文件或回归时交主线。Writer 返回改动路径、实际检查和未解决项，主 Agent 管共享文件、串行集成并负责最终验收。
4. **给出可复核结论。** 记录目标包及规则依据、约定的门禁和当前状态。已执行的检查附命令、结果或产物以及失败或未运行原因。构建由包 owner 执行，先聚焦检查再跑最终验证。校验器自身异常时，向工具链提供工作目录、命令、实际报错和相关输入，收回诊断后再判断门禁。验收或归档判断本身不授权写宿主、提交、发布或归档。

有共享资源的项目先查根规则与资源校验入口。产品变更按各包的实际入口、门禁和范围验收。
