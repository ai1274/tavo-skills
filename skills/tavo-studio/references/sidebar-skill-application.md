# 侧栏技能应用与自动配置

本页规定工程实现与验收方法，不声明已存在技能管理插件，也不证明宿主运行效果。仅在实现或修复 Tavo App 右侧边栏 → WebView → 插件内技能应用时读取。

## 先找到真实执行链

先定位目标 TPG 的规则、manifest、入口、面板源码、配置样例、执行函数及测试。工程不唯一时确认本地路径或仓库，不从多个业务插件中任选一个改，也不因缺少工程就自行新建。

从一个实际技能追踪：稳定 ID → 注册项 → 必需输入与能力 → 配置来源 → 执行函数 → 可观察效果。复用已有技能入口前，确认目标宿主的实际执行桥。不要通过执行任意 Markdown 或字符串代码补出技能运行时。

侧栏贡献与 `entry` handler 的 ID 必须一致。使用 `contributes.sidebar`、`tavo.plugin.onSidebarAction(id, handler)` 触发目标工程的面板打开逻辑；`/chat` HTML 片段由 manifest 挂载并依赖高级渲染。侧栏动作本身不创建 WebView，也不意味着面板已就绪。复用工程现有的挂载、待打开请求和清理机制。

若采用 `tavo.plugin.on/emit` 通信，按[1.12.0 声明证据](../../tavo-1-0-beta-skill/references/39-tavo-1120-mcp-evidence.md)核对目标宿主及 `minAppVersion`。自定义事件仅在同一聊天、同一插件的 `entry` 与 `/chat` 片段间传递，不用于跨插件或 `/messages`。`emit` 异步派发，不等待 handler；界面须等执行端结果，不能把事件发出当成功。遵循[官方插件开发](https://docs.tavoai.dev/cn/guides/plugin-development/)中的事件命名、JSON 数据和监听生命周期约束。

## 自动配置

先复用项目已有候选结构和选择规则；缺少规则时采用下面的默认顺序，并在项目说明与测试中固定下来。只有一个有效配置时直接使用，不为自动选择新增手选步骤或通用配置框架。

1. 每次应用和重试重新读取技能输入、当前环境与有效配置。先排除缺少必需字段、能力、权限、宿主版本或依赖的候选；兼容性根据真实 API、项目校验与必要的可用性检查判定，不能只看名称或版本号。
2. 在合格候选中优先使用用户已保存的显式首选；首选缺失或不兼容时，按项目记录的优先级选其他有效项，同优先级以稳定配置 ID 的升序确定结果，不依赖读取或对象遍历顺序。
3. 再尝试项目实际提供且通过同样校验的兼容内置默认。有效空列表按项目定义的语义处理；显式禁用或约定表示停用的空列表不能当缺失恢复默认。无合格候选时在写入效果状态前停止，指出缺失条件和修复方式，保留此前有效状态。

`tavo.plugin.config.get/all` 是同步、只读、当前插件作用域的 API；读取结果已经合并 schema 默认值与用户覆盖值，不能据此区分来源。不要虚构 `config.set`，也不要修改 `all()` 的返回对象来“保存”设置。将选出的配置传给实际执行函数；确需保存运行状态时，使用项目已有、受支持的存储与命名空间。展示配置 ID、选择原因和效果核验结果，避免显示凭据。自动配置不扩大 provider 调用、跨插件写入或安装授权。

## 应用、反馈与重试

“应用”调用该技能的实际执行函数，输入、配置和环境在首次业务写入前完成校验。执行中阻止同一操作重复提交，成功与失败均恢复可操作状态。只保存选中 ID、打开面板或收到成功回调，均不能证明技能生效。

完成后通过对应 API 或实际消费路径读回技能定义的效果，再显示成功。比如技能定义为插入输入草稿时，读回草稿核对插入内容即可；若定义为影响生成上下文，仅回读设置仍不足以证明生成 hook 生效。使用当前[官方 TavoJS](https://docs.tavoai.dev/cn/guides/javascript-api/)核对具体执行面，不能拿模拟 API 或旧宿主测试代替。

重复应用同一技能及配置应保持定义的效果一致，不重复追加内容、注册监听或创建资源。采用异步事件时将结果关联到本次请求，面板关闭重开后不误认旧结果，回执丢失先读回效果再决定是否重试。失败时报告具体阶段与原因，清理或恢复本次可回滚的状态；若效果已发生或回滚失败，明确已知状态，重试前先核验，不能盲目重放非幂等操作。切换聊天后不复用旧聊天的请求或结果。若面向当前聊天的调用因 `chat_runtime_not_ready` 被拒，只在新聊天的 `chat:opened` 中重新核对目标及条件后发起，不轮询或盲重试。[官方 TavoJS 错误说明](https://docs.tavoai.dev/cn/guides/javascript-api/)

## 最小验收

复用项目测试与 builder；没有独立构建步骤时如实说明，不编造命令。配置规则用聚焦测试验证，入口链用项目现有集成检查验证；真实宿主操作仅在已授权且环境可用时执行。

| 场景 | 验收证据 |
| --- | --- |
| 统一入口 | manifest、handler、面板链一致；从 App 右侧边栏打开面板并选择一个真实技能。 |
| 单项与多项匹配 | 单个合格项直接使用；多项及同优先级项的结果符合记录的规则，改变读取顺序仍一致。 |
| 兼容回退 | 首选缺失或无效时使用有效候选或内置默认，回读实际生效配置及技能效果。 |
| 无兼容配置 | 展示具体缺失项，执行函数未产生业务写入，此前有效状态保持；显式禁用与空列表不被恢复。 |
| 重复应用与失败重试 | 重复应用效果一致；修复失败条件后从同一面板重试成功，执行中、成功、失败状态与读回结果一致。 |
| 聊天切换与面板重开 | 旧结果不影响新聊天；重新打开可核对当前状态，监听和资源不重复。 |

项目说明记录真实安装、启动、构建及应用命令，配置优先级和结果核验步骤。交付时区分静态检查、模拟/集成测试、产物检查与 App 实测；宿主不可用时写明阻碍和复现步骤，不能将构建或事件派发成功列为真机通过。
