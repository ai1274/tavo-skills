# Tavo 插件性能实测

输入以用户操作、目标工程、数据规模和验收指标为主。缺少指标时选一个可复现的典型操作和更高负载，记录假设、测量波动和资源开销。只在影响维护位置、正确性或测试权限时请求关键输入。

1. **识别实际链路。** 从当前项目规则、manifest、入口、页面源码、测试和包命令确认宿主和运行时。沿一次用户操作追踪 WebView 资源与渲染、宿主桥接及载荷、数据处理、实际请求及服务。核对每段的输入输出、执行位置和维护源。项目内服务、宿主 API 和远端 provider 分别定位。直接调用宿主接口的插件可以没有自有服务。无对应模块标记不适用，替身环境缺少的指标标记待验证。
2. **量出基线。** 在改代码前记录版本、机器或设备、运行时、命令、脱敏输入、读写比例、并发和冷暖状态。复用项目已有测试、浏览器轨迹、运行时采样或服务统计。用同一计时定义与请求关联 ID 对齐各段，在同一运行时用单调时钟。说明时间段是包含关系还是互斥；异步重叠不能直接相加。记录有效样本数、单位、中位数、波动范围和有足够样本时的 P95。避免把启动、日志和夹具创建计入核心耗时，除非它们本身属于指标。Node VM、浏览器预览、实际 WebView 和真实服务的结果各自标明环境。
3. **只改证据指向的源。** 按下表选择适用的优化面。先用已知结果或现有回归锁定行为，再比较候选。用户要求优化且证据能定位瓶颈时，直接在当前维护源实施最小改动。无法建立可比较的基线时，交付诊断和待测条件。重复执行先检查源码、版本和同口径结果，发现同一优化已落地时直接复验。只有测量说明瓶颈仍在且找得到新的原因才继续改。
4. **复测并决定保留。** 在同机器、同输入和同工具配置重复基线命令，能交替运行时可交替采样减小时间漂移。比较结果、尾部延迟和内存等相关副作用。功能或性能退化，或收益无法和波动区分时，撤回该项自身变更并确认基线恢复。保留的变更按项目 owner 门禁生成、验证产物。授权范围按工程任务、宿主操作和外部请求分别确认。

| 优化面 | 触发证据和动作 | 完成条件 |
| --- | --- | --- |
| WebView 与桥接 | 资源瀑布查大小、数量和阻塞。主线程轨迹区分脚本、布局和绘制；长列表记录总项、可见项和实际渲染项。桥接记录事件频率、载荷字节、序列化、等待及处理时间。只针对热点处理请求、渲染范围或成批消息，并验证顺序、交互、焦点、滚动和异常反馈。 | 用相同设备、视口、冷暖状态和输入复测首屏、交互或桥接时间，核对 UI 可见结果。没有授权环境和宿主轨迹时，列出可复现操作与待验证指标。 |
| 数据处理 | 对查询、排序、去重或聚合确认输入量、读写分布、顺序、重复值和缺失值语义。比较基线与候选的时间、额外空间、索引构建和更新成本，必要时单测不同规模的拐点。 | 在典型、高负载和边界输入上核对等价结果及稳定顺序。切换阈值只采用可重复数据，计入内存和冷启动。 |
| 后端或异步资源 | 用慢请求与失败记录区分 I/O、CPU、并发、排队和清理。观察队列、等待和资源数量再决定是否限流或修复取消处理。对断连、超时及重试保留 API 和幂等语义。 | 在隔离、获授权的相同负载下比较吞吐、P95、错误率及内存、连接或队列高水位。用可控故障触发超时或取消，核对状态在明确时限内恢复且后续请求成功。 |

交付每项的操作和数据规模、瓶颈证据、源码改动和回退方法、基线与复测的命令和数值、正确性结果。目标值缺失时报告实际差值、区间和代价。待验证项写清缺少的条件及可执行命令或可重复操作。

调用示例

> $tavo 在当前插件项目分析「打开历史记录并筛选」为什么慢。用合成的典型与高负载数据记录首屏、消息处理和实际请求的阶段耗时。对定位到的瓶颈给出等价回归、前后实测和回退方式。可修改当前源码并运行本地验证。
